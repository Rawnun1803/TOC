# **UNIT IV – PUSH DOWN AUTOMATA AND POST MACHINE**

## **1. Definition and Formal Representation of PDA**

### **Definition**

A **Pushdown Automaton (PDA)** is a finite automaton with an additional memory called a Stack. It is used to recognize Context-Free Languages (CFLs).

Unlike a Finite Automaton, PDA can store and retrieve information using PUSH and POP operations.

### **Characteristics**

- **Finite Control:** Contains a finite number of states.
- **Input Tape:** Reads the input string from left to right.
- **Stack:** Stores symbols using LIFO (Last In, First Out) order.
- **PUSH:** Adds a symbol to the top of the stack.
- **POP:** Removes the topmost stack symbol.
- **Transition:** Depends on the current state, input symbol and stack top.
- **Acceptance:** Can accept by final state or empty stack.

### **Formal Representation**

A PDA is represented by a 7-tuple:

\\[ M=(Q,\Sigma,\Gamma,\delta,q_0,Z_0,F) \\]

| Symbol | Meaning              |
| ------ | -------------------- |
| Q      | Finite set of states |
| Σ      | Input alphabet       |
| Γ      | Stack alphabet       |
| δ      | Transition function  |
| q₀     | Initial state        |
| Z₀     | Initial stack symbol |
| F      | Set of final states  |

**Transition Function:**

\\[ \delta:Q\times(\Sigma\cup\\{\epsilon\\})\times\Gamma \rightarrow P(Q\times\Gamma^\*) \\]

### **PDA Architecture**

```
        ┌────────────────┐
        │ Finite Control │
        └───────┬────────┘
                │
       ┌────────┴────────┐
       ▼                 ▼
   Input Tape          Stack
   0  1  0  1          ┌───┐
                       │ A │ ← Top
                       ├───┤
                       │ B │
                       ├───┤
                       │Z₀ │
                       └───┘
```

## **2. Construction of PDA**

### **Definition**

Construction of PDA involves designing states and stack operations to recognize a given Context-Free Language.

### **Steps for Construction**

- Identify the language and its pattern.
- Determine the input and stack alphabets.
- Define the initial state and initial stack symbol.
- Use PUSH to store symbols that need to be matched later.
- Use POP to remove corresponding symbols.
- Define transitions based on input and stack top.
- Specify the acceptance condition (final state or empty stack).

### **Example: PDA for**

\\[ L=\\{0^n1^n\mid n\geq1\\} \\]

**Logic:**

- For every 0, push X onto the stack.
- When 1 starts, switch to the popping state.
- For every 1, pop one X.
- Accept when all X symbols are removed and the input is completely consumed.

**Working:**

```
Input: 0011

Read 0 → Push X
Read 0 → Push X
Read 1 → Pop X
Read 1 → Pop X

Stack: Z₀
       ↓
     ACCEPT
```

### **Transition Rules**

| Current State | Input | Stack Top | Next State | Stack Replacement |
| ------------- | ----- | --------- | ---------- | ----------------- |
| q₀            | 0     | Z₀        | q₀         | XZ₀               |
| q₀            | 0     | X         | q₀         | XX                |
| q₀            | 1     | X         | q₁         | ε                 |
| q₁            | 1     | X         | q₁         | ε                 |
| q₁            | ε     | Z₀        | qf         | Z₀                |

## **3. PDA Transition Diagram and Transition Table**

### **Transition Diagram**

A PDA Transition Diagram is a graphical representation of the states and transitions of a PDA.

**Important components:**

- States are represented by circles.
- Initial state has an incoming arrow.
- Final state is represented by a double circle.
- Directed arrows represent transitions.
- Transition labels specify input and stack operations.

### **Transition Label**

\\[ a,X\rightarrow\gamma \\]

Where:

- a = Input symbol
- X = Current stack top
- γ = Symbol or string replacing X

**Example:**

\\[ 0,Z_0\rightarrow XZ_0 \\]

Meaning: Read 0, remove Z₀ and replace it with XZ₀. Thus, X is pushed above Z₀.

### **Transition Diagram Example**

```
             0,Z₀→XZ₀
          ┌─────────────┐
          ▼             │
       → (q₀) ──────────┘
          │
          │ 1,X→ε
          ▼
        (q₁) ──1,X→ε──┐
          ▲            │
          └────────────┘
          │
          │ ε,Z₀→Z₀
          ▼
        ((qf))
```

### **Transition Table**

A transition table represents PDA operations in tabular form.

| Current State | Input | Stack Top | Next State | Stack Replacement |
| ------------- | ----- | --------- | ---------- | ----------------- |
| q₀            | 0     | Z₀        | q₀         | XZ₀               |
| q₀            | 0     | X         | q₀         | XX                |
| q₀            | 1     | X         | q₁         | ε                 |
| q₁            | 1     | X         | q₁         | ε                 |
| q₁            | ε     | Z₀        | qf         | Z₀                |

### **Difference Between Transition Diagram and Transition Table**

| Transition Diagram               | Transition Table                           |
| -------------------------------- | ------------------------------------------ |
| Graphical representation.        | Tabular representation.                    |
| Uses circles and arrows.         | Uses rows and columns.                     |
| Easier to visualize transitions. | Easier to list transitions systematically. |

## **4. Deterministic Pushdown Automaton (DPDA)**

### **Definition**

A **Deterministic Pushdown Automaton (DPDA)** is a PDA in which at most one transition is possible for a given state, input symbol and stack-top symbol.

### **Characteristics**

- It has a unique computation path for a given input.
- It does not allow multiple choices for the same configuration.
- It uses a stack for storing and retrieving information.
- It can perform PUSH, POP and ε-transitions.
- Its ε-transitions must satisfy the determinism restriction: an ε-move and an input-consuming move cannot both be enabled for the same state and stack top.
- It recognizes Deterministic Context-Free Languages (DCFLs).
- It is used in deterministic parsing and compiler design.

### **Example**

\\[ L=\\{0^n1^n\mid n\geq1\\} \\]

A DPDA can recognize this language by:

- Pushing X for every 0.
- Switching to the popping state when 1 begins.
- Popping X for every 1.
- Accepting when the input is finished and only the initial stack marker remains.

## **5. Non-Deterministic Pushdown Automaton (NPDA)**

### **Definition**

A **Non-Deterministic Pushdown Automaton (NPDA)** is a PDA in which multiple transitions may be possible for the same current state, input symbol and stack-top symbol.

### **Characteristics**

- Multiple transitions may be available for the same configuration.
- It can have multiple possible computation paths.
- It uses a stack for storing information.
- It supports ε-transitions.
- It can nondeterministically choose between different transitions.
- An input is accepted if at least one computation path accepts.
- It recognizes all Context-Free Languages (CFLs).
- It is used in CFG recognition and theoretical parsing.

### **Example: Palindrome Language**

\\[ L=\\{ww^R\mid w\in\\{0,1\\}^\*\\} \\]

**Working:**

- Push the first half of the input onto the stack.
- Nondeterministically guess the midpoint.
- Start popping and compare symbols with the remaining input.
- Accept if all symbols match and the input is completely consumed.

**Why NPDA?**

It can guess the midpoint without requiring a special middle marker.

### **Diagram**

```
          Input String
               |
               ▼
          ┌─────────┐
          │  NPDA   │
          └────┬────┘
               |
         ┌─────┼─────┐
         ▼     ▼     ▼
       Path 1 Path 2 Path 3
         |     |     |
       Reject Accept Reject
```

## **6. Difference Between DPDA and NPDA**

| DPDA                                        | NPDA                                    |
| ------------------------------------------- | --------------------------------------- |
| Deterministic Pushdown Automaton.           | Non-Deterministic Pushdown Automaton.   |
| At most one transition for a configuration. | Multiple transitions may be possible.   |
| Has a unique computation path.              | Can have multiple computation paths.    |
| Does not allow conflicting transitions.     | Allows multiple choices of transitions. |
| Recognizes DCFLs.                           | Recognizes all CFLs.                    |
| Less powerful in language recognition.      | More powerful in language recognition.  |
| Used in deterministic parsing.              | Used in general CFG recognition.        |

### **Relationship**

\\[ DCFL\subset CFL \\]

\\[ L(DPDA)\subset L(NPDA) \\]

### **Diagram**

```

       ┌──────────────────────────┐
       │                          │
       │    ┌────────────────┐    │
       │    │ Deterministic  │    │
       │    │ CFL (DCFL)     │    │
       │    └────────────────┘    │

```

## **7. Conversion of CFG to PDA**

### **Definition**

A Context-Free Grammar (CFG) can be converted into an equivalent Pushdown Automaton (PDA) that recognizes the same language.

The PDA uses its stack to simulate the production rules of the grammar.

### **Conversion Steps**

- Create an initial state and push the start symbol S onto the stack.
- For every production rule, introduce an ε-transition.
- Replace a non-terminal at the stack top with its production body.
- When a terminal appears at the stack top, match it with the current input symbol.
- Pop the matched terminal and consume the input symbol.
- For ε-productions, remove the corresponding non-terminal without consuming input.
- Accept when the entire input is consumed and the stack is empty (under empty-stack acceptance).

### **Example**

Consider the CFG:

\\[ S\rightarrow 0S1\mid\epsilon \\]

Language:

\\[ L=\\{0^n1^n\mid n\geq0\\} \\]

**Production Rules:**

```
S → 0S1
S → ε
```

**PDA Working:**

- Push S onto the stack.
- Replace S with 0S1 using an ε-transition.
- Replace S with ε when required.
- Match terminals with the input symbols.
- Accept when the input is consumed and the stack is empty.

### **General Transition Rules**

For a production:

\\[ A\rightarrow\alpha \\]

The PDA uses:

\\[ \delta(q,\epsilon,A)\ni(q,\alpha) \\]

For terminal matching:

\\[ \delta(q,a,a)\ni(q,\epsilon) \\]

The leftmost symbol of the replacement string is assumed to be placed at the top of the stack.

### **Diagram**

```
        CFG
         |
         ▼
   Production Rules
         |
         ▼
  Push Start Symbol
         |
         ▼
 Expand Non-Terminals
         |
         ▼
   Match Terminals
         |
         ▼
        PDA
```

## **8. Conversion of PDA to CFG**

### **Definition**

A Pushdown Automaton can be converted into an equivalent Context-Free Grammar that generates the same language.

The conversion uses grammar variables to represent the possible stack behaviour of the PDA.

### **Conversion Steps**

- Start with the given PDA.
- Convert it into a suitable standard form, generally accepting by empty stack.
- Introduce grammar variables of the form \\([pAq]\\).
- Here, p represents the starting state, A represents the stack symbol and q represents the ending state.
- Create a start variable representing the initial configuration.
- Examine the PDA transitions and construct corresponding grammar productions.
- Introduce intermediate states where necessary to represent multiple pushed symbols.
- Include the input symbols consumed by transitions as grammar terminals.
- The resulting CFG generates the same language as the original PDA.

### **Meaning of Grammar Variable**

\\[ [pAq] \\]

It represents all strings that take the PDA from state p with A on top of the stack to state q after removing A.

### **Conversion Diagram**

```
          PDA
           |
           ▼
     Normalize PDA
           |
           ▼
   Identify States and
      Stack Symbols
           |
           ▼
     Create Variables
         [pAq]
           |
           ▼
    Generate Productions
           |
           ▼
          CFG
```

### **Important Relationship**

\\[ CFG\equiv NPDA \\]

Both CFG and NPDA have equivalent language recognition power.

## **9. Power and Limitations of PDA**

### **Power of PDA**

- **Stack Memory:** Provides additional memory compared to finite automata.
- **CFL Recognition:** Recognizes Context-Free Languages.
- **Nested Structures:** Can recognize balanced parentheses and nested expressions.
- **Matching Symbols:** Can recognize \\(L=\\{0^n1^n\mid n\geq0\\}\\).
- **Grammar Equivalence:** Every CFG has an equivalent NPDA.
- **Compiler Design:** Used in syntax analysis and parsing.

### **Limitations of PDA**

- It can access only the topmost stack symbol.
- It follows LIFO (Last In, First Out) memory access.
- It cannot directly access arbitrary stack positions.
- It cannot recognize all Context-Sensitive Languages.
- It cannot recognize languages such as:

\\[ L=\\{a^nb^nc^n\mid n\geq1\\} \\]

\- It has less computational power than a Turing Machine.

### **Comparison Between FA, PDA and TM**

| Finite Automaton              | Pushdown Automaton            | Turing Machine               |
| ----------------------------- | ----------------------------- | ---------------------------- |
| Has finite control only.      | Has finite control and stack. | Has finite control and tape. |
| No additional memory.         | Uses stack memory.            | Uses read/write tape memory. |
| Recognizes Regular Languages. | NPDA recognizes CFLs.         | Recognizes RE languages.     |
| Limited computational power.  | More powerful than FA.        | More powerful than PDA.      |

### **Power Relationship**

```
Regular Languages
        ⊂
Context-Free Languages
        ⊂
Recursively Enumerable Languages
```

\\[ Regular\subset CFL\subset RE \\]

## **10. Post Machine – Definition and Construction**

### **Definition**

A **Post Machine** is an abstract mathematical model of computation introduced by Emil Post. It performs computations using a tape divided into cells, a read/write head and a finite set of instructions.

It is computationally equivalent to a Turing Machine.

### **Characteristics**

- **Tape:** Consists of cells used to store information.
- **Tape Symbols:** Cells may contain symbols such as 0, 1 or blank.
- **Read/Write Head:** Reads and modifies the contents of the current cell.
- **Instructions:** Executes a finite set of instructions to perform computations.
- **Movement:** The head moves left or right according to instructions.
- **Conditional Branching:** The next instruction can depend on the contents of the current cell.
- **Halting:** The machine stops when it reaches a designated halt instruction.
- **Computational Power:** Can perform general algorithmic computations, equivalent in power to a Turing Machine.

### **Basic Instructions**

A common Post-style machine uses instructions such as:

| Instruction | Meaning                                  |
| ----------- | ---------------------------------------- |
| MARK        | Mark the current cell.                   |
| ERASE       | Erase the current cell.                  |
| RIGHT       | Move head one cell right.                |
| LEFT        | Move head one cell left.                 |
| IF MARKED   | Check whether current cell is marked.    |
| GOTO        | Transfer control to another instruction. |
| HALT        | Stop execution.                          |

### **Construction of Post Machine**

To construct a Post Machine:

- Identify the problem and its required operations.
- Define the initial tape contents.
- Place the read/write head at the starting position.
- Write the sequence of instructions.
- Use MARK and ERASE to modify tape contents.
- Use LEFT and RIGHT to move the head.
- Use conditional instructions to control execution.
- Use GOTO to repeat or branch between instructions.
- Use HALT to terminate the computation.

### **Diagram – Post Machine**

```
        ┌─────────────────┐
        │  Instructions   │
        │   (Program)     │
        └────────┬────────┘
                 │
                 ▼
           Read/Write Head
                 │
                 ▼
       ┌────┬────┬────┬────┐
       │ 1  │ 0  │ 1  │ B  │
       └────┴────┴────┴────┘
               Tape
```

### **Difference Between PDA and Post Machine**

| PDA                            | Post Machine                              |
| ------------------------------ | ----------------------------------------- |
| Uses a stack as memory.        | Uses a tape as memory.                    |
| Stack follows LIFO order.      | Tape allows movement in both directions.  |
| Recognizes CFLs using NPDA.    | Has computational power equivalent to TM. |
| Can access only the stack top. | Can read and write the current tape cell. |
| Less powerful than TM.         | Equivalent in computational power to TM.  |
