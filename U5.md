# **UNIT V – TURING MACHINE AND COMPUTATIONAL COMPLEXITY**

## **1. Turing Machine – Definition and Construction**

### **1.1 Definition**

A **Turing Machine (TM)** is an abstract mathematical model of computation used to recognize languages and solve computational problems.

It consists of an infinite tape, a read/write head and a finite control unit that performs operations according to transition rules.

### **1.2 Characteristics of Turing Machine**

1. **Infinite Tape:** The tape is divided into cells and is used to store input, output and intermediate results.
2. **Read/Write Head:** The head reads the current tape symbol, writes a new symbol and moves either left or right.
3. **Finite Control:** It consists of a finite number of states that control the execution of the machine.
4. **Input:** The input string is initially placed on the tape, while the remaining cells contain blank symbols.
5. **Tape Alphabet:** It contains all input symbols and additional symbols required during computation.
6. **Transition Function:** It determines the next state, symbol to be written and direction of head movement.
7. **Initial State:** The machine begins its computation from a designated starting state.
8. **Halting States:** The machine stops when it reaches an accepting or rejecting state.
9. **Language Recognition:** A string is accepted if the machine reaches its accepting state. The collection of all accepted strings forms the language recognized by the TM.

### **1.3 Formal Definition**

A Turing Machine is represented by a 7-tuple:

\\[ M=(Q,\Sigma,\Gamma,\delta,q_0,B,F) \\]

| Symbol | Description          |
| ------ | -------------------- |
| Q      | Finite set of states |
| Σ      | Input alphabet       |
| Γ      | Tape alphabet        |
| δ      | Transition function  |
| q₀     | Initial state        |
| B      | Blank symbol         |
| F      | Set of final states  |

**Transition Function:**

\\[ \delta(q,a)=(p,b,D) \\]

Where:

- q = Current state
- a = Symbol being read
- p = Next state
- b = Symbol to be written
- D = Direction (L or R)

### **1.4 Turing Machine Architecture**

```
         ┌───────────────────┐
         │   Finite Control  │
         │    (States)       │
         └─────────┬─────────┘
                   │
                   ▼
             Read/Write Head
                   │
                   ▼
    ┌─────┬─────┬─────┬─────┬─────┐
    │  0  │  1  │  0  │  B  │  B  │
    └─────┴─────┴─────┴─────┴─────┘
                  Tape
```

### **1.5 Construction of Turing Machine**

**Example: Construct a TM for the language:**

\\[ L=\\{0^n1^n\mid n\geq 1\\} \\]

**Logic:**

1. Start scanning the tape from the leftmost symbol.
2. Replace the first unmarked 0 with X.
3. Move right and search for the first unmarked 1.
4. Replace that 1 with Y.
5. Move left towards the beginning of the tape.
6. Repeat the process for all remaining unmarked 0s and 1s.
7. When no unmarked 0 remains, check whether any unmarked 1 remains.
8. If only X and Y are present, accept the string.
9. If the symbols are unmatched or incorrectly ordered, reject the string.

**Example:**

```
Input: 0011

0011
X0Y1
XXYY

ACCEPT
```

## **2. Variants of Turing Machine – Multi-Tape TM and Universal TM**

### **2.1 Multi-Tape Turing Machine**

A Multi-Tape Turing Machine is a variant of a standard Turing Machine that consists of multiple tapes, with each tape having its own read/write head.

### **2.2 Characteristics of Multi-Tape TM**

1. **Multiple Tapes:** It consists of two or more tapes instead of a single tape.
2. **Separate Heads:** Each tape has an independent read/write head.
3. **Input Tape:** The input is initially placed on the first tape, while the other tapes are blank.
4. **Simultaneous Reading:** In each transition, the machine reads symbols from all tape heads.
5. **Simultaneous Writing:** It can write new symbols on multiple tapes in one transition.
6. **Independent Movement:** Each head can move independently in the left or right direction (and may stay stationary in some definitions).
7. **Transition Function:** The next move depends on the current state and the symbols read from all tapes.
8. **Efficiency:** It simplifies complex computations and can reduce the number of steps required.
9. **Equivalent Power:** It has the same computational power as a Single-Tape TM, although the number of computation steps may differ.

### **2.3 Diagram – Multi-Tape TM**

```
             Finite Control
                   |
          ┌────────┼────────┐
          ▼        ▼        ▼
        Head 1   Head 2   Head 3

Tape 1:  0   1   0   B   B
Tape 2:  X   Y   B   B   B
Tape 3:  1   1   0   0   B
```

### **2.4 Universal Turing Machine (UTM)**

A Universal Turing Machine is a special Turing Machine that can simulate the working of any other Turing Machine using its encoded description and input.

### **2.5 Characteristics of Universal TM**

1. **Universal Machine:** It is a general-purpose Turing Machine capable of simulating other Turing Machines.
2. **Input:** It takes the encoded description of another TM along with its input string.
3. **Encoding:** The structure and transition rules of the given machine are represented in an encoded form.
4. **Simulation:** It simulates the states, tape operations and transitions of the given machine.
5. **General Purpose:** A single UTM can perform the computations of different Turing Machines.
6. **Program Execution:** It works on the principle of storing a program and executing it on given input.
7. **Computational Power:** It has the same computational power as an ordinary Turing Machine.
8. **Applications:** It provides the theoretical foundation for general-purpose computers and stored-program architecture.
9. **Importance:** It demonstrates that one machine can simulate any algorithmically specified computation.

### **2.6 Diagram – Universal Turing Machine**

```
    Encoded TM (M) + Input (w)
                 |
                 ▼
       ┌───────────────────┐
       │ Universal Turing  │
       │     Machine       │
       └─────────┬─────────┘
                 |
                 ▼
          Simulates M(w)
                 |
          ┌──────┴──────┐
          ▼             ▼
        Accept         Reject
```

### **2.7 Difference Between Single-Tape and Multi-Tape TM**

| Single-Tape TM                                  | Multi-Tape TM                               |
| ----------------------------------------------- | ------------------------------------------- |
| Contains one tape.                              | Contains multiple tapes.                    |
| Has one read/write head.                        | Has multiple read/write heads.              |
| Uses a single tape for computation.             | Uses multiple tapes for computation.        |
| May require more transitions for certain tasks. | Can simplify computations.                  |
| Same computational power as Multi-Tape TM.      | Same computational power as Single-Tape TM. |

### **2.8 Difference Between Multi-Tape TM and Universal TM**

| Multi-Tape TM                            | Universal TM                                            |
| ---------------------------------------- | ------------------------------------------------------- |
| Contains multiple tapes.                 | Simulates other Turing Machines.                        |
| Uses separate heads.                     | Uses an encoded machine description.                    |
| Designed to simplify computation.        | Designed for general-purpose simulation.                |
| Multiple tapes store computational data. | Stores information describing another TM and its input. |

## **3. Halting Problem and Church-Turing Thesis**

### **3.1 Halting Problem**

The Halting Problem is the problem of determining whether a given Turing Machine will eventually stop or continue running indefinitely for a particular input.

### **3.2 Characteristics of Halting Problem**

1. **Definition:** It determines whether a given Turing Machine halts on a particular input.
2. **Input:** It takes an encoded Turing Machine M and an input string w.
3. **Halting:** A machine halts when it enters an accepting or rejecting state.
4. **Non-Halting:** A machine does not halt if it continues executing indefinitely.
5. **Decision Requirement:** The problem asks whether M will halt on input w.
6. **Undecidability:** No Turing Machine can correctly determine the halting behaviour of every possible machine and input.
7. **Contradiction:** Its undecidability is proved using a self-reference argument and contradiction.
8. **Importance:** It establishes the limitations of algorithmic computation.
9. **Applications:** It is important in program verification, debugging and the study of computational limitations.

### **3.3 Diagram – Halting Problem**

```
       Turing Machine (M)
                +
          Input String (w)
                |
                ▼
        Halting Problem
                |
         ┌──────┴──────┐
         ▼             ▼
       HALTS        DOES NOT
                     HALT
```

*This represents the question being asked. An algorithm that correctly classifies every possible input does not exist.*

### **3.4 Church-Turing Thesis**

The Church-Turing Thesis states that every function that can be computed using an effective algorithm can also be computed by a Turing Machine.

### **3.5 Characteristics of Church-Turing Thesis**

1. **Definition:** It establishes the Turing Machine as a mathematical model of effective computation.
2. **Proposed By:** It is based on the independent work of Alonzo Church and Alan Turing.
3. **Computability:** Every effectively computable function can be computed by a Turing Machine.
4. **Equivalent Models:** Turing Machines, Lambda Calculus and Recursive Functions have equivalent computational power.
5. **General Model:** It provides a standard model for understanding algorithmic computation.
6. **Limitations:** It does not claim that every mathematical problem can be solved using a computer.
7. **Not a Theorem:** It is a thesis rather than a mathematical theorem because effective computation is an informal concept.
8. **Importance:** It provides the theoretical foundation of computability theory.
9. **Applications:** It is useful in studying programming languages, algorithms and computational limitations.

### **3.6 Difference Between Halting Problem and Church-Turing Thesis**

| Halting Problem                         | Church-Turing Thesis                        |
| --------------------------------------- | ------------------------------------------- |
| It is a computational problem.          | It is a principle about computation.        |
| Determines whether a TM halts.          | Defines the scope of effective computation. |
| It is undecidable.                      | It is not a formal mathematical theorem.    |
| Establishes limitations of computation. | Establishes a general model of computation. |

## **4. Recursive and Recursively Enumerable Languages**

### **4.1 Recursive Language**

A language is called Recursive or Decidable if there exists a Turing Machine that always halts for every input and correctly accepts or rejects it.

### **4.2 Characteristics of Recursive Language**

1. **Definition:** A language is recursive if a Turing Machine can decide whether any given string belongs to it.
2. **Decidability:** There exists an algorithm to determine membership of every input string.
3. **Acceptance:** If the input belongs to the language, the machine enters the accepting state.
4. **Rejection:** If the input does not belong to the language, the machine enters the rejecting state.
5. **Halting:** The machine always halts for every possible input.
6. **Finite Execution:** Every input requires a finite number of computational steps.
7. **Complement:** The complement of a recursive language is also recursive.
8. **Relationship:** Every recursive language is also recursively enumerable.
9. **Example:** \\(L=\\{0^n1^n\mid n\geq 0\\}\\) is recursive because a TM can always decide whether a string follows this pattern.

### **4.3 Recursively Enumerable Language (RE)**

A language is called Recursively Enumerable if there exists a Turing Machine that accepts every string belonging to the language but may run forever for strings that do not belong to it.

### **4.4 Characteristics of Recursively Enumerable Language**

1. **Definition:** A language is RE if a Turing Machine can recognize all strings belonging to it.
2. **Recognition:** The machine recognizes and accepts valid strings.
3. **Acceptance:** If the input belongs to the language, the machine eventually halts and accepts it.
4. **Rejection:** If the input does not belong to the language, the machine may reject it or run forever.
5. **Halting:** The machine is not guaranteed to halt for every input.
6. **Semi-Decidable:** RE languages are also called Turing-recognizable or semi-decidable languages.
7. **Complement:** The complement of an RE language is not necessarily RE.
8. **Relationship:** Every recursive language is RE, but every RE language is not necessarily recursive.
9. **Example:** The language of encoded TM-input pairs for which the TM halts is RE but not recursive.

### **4.5 Difference Between Recursive and Recursively Enumerable Languages**

| Recursive Language              | Recursively Enumerable Language                |
| ------------------------------- | ---------------------------------------------- |
| Also called Decidable Language. | Also called Turing-Recognizable Language.      |
| Machine always halts.           | Machine may run forever.                       |
| Accepts valid strings.          | Accepts valid strings.                         |
| Rejects invalid strings.        | May reject or loop forever on invalid strings. |
| Membership is decidable.        | Membership is not necessarily decidable.       |
| Complement is recursive.        | Complement is not necessarily RE.              |
| Every recursive language is RE. | Every RE language need not be recursive.       |

### **4.6 Relationship Diagram**

```
       Recursively Enumerable (RE)
       ┌──────────────────────────┐
       │                          │
       │    Recursive Languages   │
       │      ┌────────────┐      │
       │      │ Decidable  │      │
       │      │ Languages  │      │
       │      └────────────┘      │
       │                          │
       └──────────────────────────┘
```

\\[ Recursive \subset RE \\]

## **5. Decidability and Undecidability**

### **5.1 Decidability**

A problem is called Decidable if there exists an algorithm or Turing Machine that produces the correct Yes/No answer and halts for every possible input.

### **5.2 Characteristics of Decidability**

1. **Definition:** A problem is decidable if a Turing Machine can solve it for every input.
2. **Termination:** The machine always terminates after a finite number of steps.
3. **Yes/No Output:** It produces a definite answer, either Yes or No.
4. **Correctness:** The machine provides the correct answer for every input.
5. **Recursive Language:** A language is decidable if it is recursive.
6. **Membership Testing:** It determines whether a given string belongs to a particular language.
7. **Algorithm:** A finite and well-defined procedure exists to solve the problem.
8. **Examples:** Checking whether a string is a palindrome or whether a number is even.
9. **Importance:** It identifies problems that can be completely solved using algorithms.

### **5.3 Undecidability**

A problem is called Undecidable if no Turing Machine exists that can correctly solve the problem and halt for every possible input.

### **5.4 Characteristics of Undecidability**

1. **Definition:** A problem is undecidable if no algorithm can solve all its instances correctly.
2. **No General Algorithm:** There is no universal procedure that provides the correct answer for every input.
3. **Non-Termination:** A proposed recognizer may run forever for some inputs.
4. **Turing Machine:** Undecidability is studied using the limitations of Turing Machines.
5. **Halting Problem:** Determining whether an arbitrary TM halts on a given input is undecidable.
6. **Reduction:** Undecidability can be proved by reducing a known undecidable problem to another problem.
7. **Contradiction:** Proofs often use contradiction to show that a hypothetical decider cannot exist.
8. **Limitations:** Some problems cannot be solved by any general-purpose algorithm.
9. **Examples:** Halting Problem, TM Acceptance Problem and Post Correspondence Problem.

### **5.5 Difference Between Decidable and Undecidable Problems**

| Decidable                           | Undecidable                                       |
| ----------------------------------- | ------------------------------------------------- |
| Can be solved by an algorithm.      | Cannot be solved by any algorithm for all inputs. |
| Machine always halts.               | No correct decider always halts.                  |
| Produces a definite Yes/No answer.  | No universal decision procedure exists.           |
| Corresponds to recursive languages. | Corresponds to non-recursive decision languages.  |
| Finite computation is guaranteed.   | No general halting guarantee is possible.         |
| Example: Palindrome checking.       | Example: Halting Problem.                         |

### **5.6 Examples**

| Decidable Problems                             | Undecidable Problems            |
| ---------------------------------------------- | ------------------------------- |
| Checking whether a number is even.             | Halting Problem.                |
| Checking whether a string is a palindrome.     | TM Acceptance Problem.          |
| Membership testing for regular languages.      | Post Correspondence Problem.    |
| Membership testing for context-free languages. | General TM equivalence problem. |

## **6. Class P and NP – Definitions and Examples**

### **6.1 Class P**

Class P (Polynomial Time) is the class of decision problems that can be solved by a Deterministic Turing Machine in polynomial time.

### **6.2 Characteristics of P**

1. **Definition:** P is the class of decision problems solvable in polynomial time.
2. **Deterministic Machine:** Problems are solved using a Deterministic Turing Machine.
3. **Polynomial Time:** Execution time is bounded by a polynomial function such as \\(O(n)\\), \\(O(n^2)\\) or \\(O(n^3)\\).
4. **Efficiency:** These problems are generally considered computationally tractable.
5. **Input Size:** Execution time depends on the size of the input.
6. **Solution:** The machine directly computes the correct Yes/No answer.
7. **Algorithms:** Polynomial-time algorithms are used to solve problems such as graph connectivity and shortest-path decision problems.
8. **Examples:** Graph connectivity, primality testing and shortest-path decision problem.
9. **Importance:** P represents problems that can be efficiently solved by a deterministic algorithm.

### **6.3 Class NP**

Class NP (Nondeterministic Polynomial Time) is the class of decision problems whose proposed solutions can be verified in polynomial time by a Deterministic Turing Machine.

### **6.4 Characteristics of NP**

1. **Definition:** NP is the class of decision problems whose solutions can be verified in polynomial time.
2. **Nondeterministic Machine:** Problems can be solved in polynomial time using a Nondeterministic Turing Machine.
3. **Verification:** A given solution or certificate can be checked efficiently.
4. **Polynomial Time:** Verification takes polynomial time with respect to the input size.
5. **Guessing:** A nondeterministic machine can conceptually guess a possible solution.
6. **Acceptance:** If at least one guessed solution is valid, the machine accepts the input.
7. **Relationship:** Every problem in P is also in NP.
8. **Examples:** SAT, Hamiltonian Cycle and the decision version of Travelling Salesman Problem.
9. **Importance:** NP helps classify problems whose solutions are easy to verify, even if finding them may be difficult.

### **6.5 Difference Between P and NP**

| Class P                            | Class NP                                        |
| ---------------------------------- | ----------------------------------------------- |
| Polynomial-time solvable problems. | Polynomial-time verifiable problems.            |
| Uses deterministic computation.    | Uses nondeterministic computation.              |
| Solution can be found efficiently. | Given solution can be verified efficiently.     |
| Generally considered tractable.    | May contain computationally difficult problems. |
| Every P problem is in NP.          | Every NP problem is not known to be in P.       |
| Example: Graph connectivity.       | Example: SAT problem.                           |

### **6.6 Relationship Between P and NP**

\\[ P\subseteq NP \\]

```
        ┌────────────────────┐
        │         NP         │
        │                    │
        │    ┌─────────┐     │
        │    │    P    │     │
        │    └─────────┘     │
        │                    │
        └────────────────────┘
```

### **6.7 P vs NP Problem**

1. P vs NP is one of the most important unsolved problems in computer science.
2. It asks whether every problem whose solution can be verified in polynomial time can also be solved in polynomial time.
3. If P = NP, all problems in NP can be solved in polynomial time.
4. If P ≠ NP, some problems in NP cannot be solved in polynomial time.

## **7. NP-Hard and NP-Complete – Differences and Pictorial Representation**

### **7.1 NP-Hard**

A problem is called NP-Hard if every problem in NP can be reduced to it in polynomial time.

### **7.2 Characteristics of NP-Hard**

1. **Definition:** NP-Hard problems are at least as hard as every problem in NP.
2. **Reduction:** Every problem in NP can be transformed into an NP-Hard problem using polynomial-time reduction.
3. **Difficulty:** They represent computationally challenging problems.
4. **Membership:** An NP-Hard problem does not necessarily belong to NP.
5. **Verification:** Its solution is not necessarily verifiable in polynomial time.
6. **Problem Type:** NP-Hard problems may be decision, optimization or even undecidable problems.
7. **Relationship:** Every NP-Complete problem is NP-Hard.
8. **Examples:** Travelling Salesman optimization problem and the Halting Problem (under standard polynomial-time many-one reductions).
9. **Importance:** NP-Hard classification helps identify problems for which efficient general algorithms are not known.

### **7.3 NP-Complete**

A problem is called NP-Complete if it belongs to NP and is also NP-Hard.

### **7.4 Characteristics of NP-Complete**

1. **Definition:** NP-Complete problems are the hardest problems within the class NP.
2. **Membership:** Every NP-Complete problem belongs to NP.
3. **Verification:** A proposed solution can be verified in polynomial time.
4. **Reduction:** Every problem in NP can be reduced to an NP-Complete problem in polynomial time.
5. **Difficulty:** Finding a solution is not known to be possible in polynomial time for these problems.
6. **Relationship:** Every NP-Complete problem is NP-Hard, but every NP-Hard problem need not be NP-Complete.
7. **Polynomial Solution:** If any NP-Complete problem is solved in polynomial time, then P = NP.
8. **Examples:** SAT, 3-SAT, Clique Decision Problem and Hamiltonian Cycle Problem.
9. **Importance:** NP-Complete problems help identify computationally difficult problems and study their complexity.

### **7.5 Difference Between NP-Hard and NP-Complete**

| NP-Hard                                             | NP-Complete                                           |
| --------------------------------------------------- | ----------------------------------------------------- |
| At least as hard as every problem in NP.            | Hardest problems within NP.                           |
| Need not belong to NP.                              | Must belong to NP.                                    |
| Need not have polynomial-time verifiable solutions. | Solutions are polynomial-time verifiable.             |
| Can be decision or optimization problems.           | Must be decision problems.                            |
| Can even be undecidable.                            | Always decidable because they belong to NP.           |
| Every NP-Complete problem is NP-Hard.               | Every NP-Hard problem is not necessarily NP-Complete. |
| Example: TSP optimization.                          | Example: SAT and 3-SAT.                               |

### **7.6 Pictorial Representation**

```
                NP-HARD
       ┌────────────────────────┐
       │                        │
       │          NP            │
       │    ┌────────────┐      │
       │    │            │      │
       │    │ NP-COMPLETE│      │
       │    │            │      │
       │    └────────────┘      │
       │                        │
       │  Other NP-Hard Problems│
       │                        │
       └────────────────────────┘
```

**Remember:**

NP-Complete is the intersection of NP and NP-Hard.

\\[ NP\text{-Complete}=NP\cap NP\text{-Hard} \\]

### **7.7 Important Examples**

| Problem                      | Classification |
| ---------------------------- | -------------- |
| SAT                          | NP-Complete    |
| 3-SAT                        | NP-Complete    |
| Hamiltonian Cycle (Decision) | NP-Complete    |
| Clique (Decision)            | NP-Complete    |
| TSP (Decision)               | NP-Complete    |
| TSP (Optimization)           | NP-Hard        |

### **7.8 Important Relationships**

\\[ P\subseteq NP \\]

\\[ NP\text{-Complete}\subseteq NP \\]

\\[ NP\text{-Complete}\subseteq NP\text{-Hard} \\]
