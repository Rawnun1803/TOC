# **Unit II – Regular Expressions and Languages**

## **1. Definition of Regular Expression**

A **Regular Expression (RE)** is a mathematical notation used to represent a regular language over a given alphabet.

- It describes a set of strings using symbols and operators.
- It is used to represent patterns in strings.
- Every regular expression has an equivalent Finite Automaton (FA).
- It is widely used in pattern matching and text processing.

**Basic regular expressions:**

- \\(\emptyset\\) – Represents an empty language.
- \\(\epsilon\\) – Represents a language containing only the empty string.
- \\(a\\) – Represents the language containing the string `a`.

**Example:**

\\[ RE=(a+b)^\* \\]

Represents all possible strings over the alphabet \\(\\{a,b\\}\\), including ε.

## **2. Operators of Regular Expressions**

Regular Expressions mainly use three basic operators.

**1. Union (+ or |)**

- Represents a choice between two expressions.
- Accepts strings belonging to either expression.

Example:

\\[ a+b \\]

Language: \\(\\{a,b\\}\\)

**2. Concatenation (.)**

- Combines two expressions in sequence.
- A string from the first expression is followed by a string from the second.

Example:

\\[ ab \\]

Language: \\(\\{ab\\}\\)

**3. Kleene Star (\*)**

- Represents zero or more repetitions of an expression.
- Includes the empty string ε.

Example:

\\[ a^\* \\]

Language: \\(\\{\epsilon,a,aa,aaa,\ldots\\}\\)

**Operator precedence:**

1. Kleene Star (\*)
2. Concatenation (.)
3. Union (+)

## **3. Identities and Properties of Regular Expressions**

Regular expressions follow several algebraic identities that help in simplifying and manipulating expressions.

| Identity                               | Property                             |
| -------------------------------------- | ------------------------------------ |
| \\(R+\emptyset=R\\)                    | Union with empty language            |
| \\(R+\epsilon\neq R\\) generally       | ε is a string, not an empty language |
| \\(R+\emptyset=R\\)                    | Union identity                       |
| \\(R+R=R\\)                            | Idempotent law                       |
| \\(R+S=S+R\\)                          | Commutative law                      |
| \\((R+S)+T=R+(S+T)\\)                  | Associative union                    |
| \\((RS)T=R(ST)\\)                      | Associative concatenation            |
| \\(R(S+T)=RS+RT\\)                     | Left distributive law                |
| \\((R+S)T=RT+ST\\)                     | Right distributive law               |
| \\(R\epsilon=\epsilon R=R\\)           | Concatenation identity               |
| \\(R\emptyset=\emptyset R=\emptyset\\) | Annihilation law                     |
| \\(\emptyset^\*=\epsilon\\)            | Star of empty language               |
| \\(\epsilon^\*=\epsilon\\)             | Star of ε                            |
| \\(R^\*=\epsilon+RR^\*\\)              | Kleene star identity                 |
| \\(R^{\*\*}=R^\*\\)                    | Idempotent star                      |

**Important:** Union and concatenation are associative, but concatenation is not commutative in general.

\\[ RS\neq SR \\]

For example, \\(ab\neq ba\\).

## **4. Equivalence of Two Regular Expressions**

Two regular expressions are equivalent if they represent the same language.

**Condition:**

\\[ L(R_1)=L(R_2) \\]

Where \\(L(R)\\) represents the language generated by regular expression R.

**Methods to check equivalence:**

1. Compare the languages generated by both expressions.
2. Simplify both expressions using regular expression identities.
3. Convert both expressions into Finite Automata.
4. Compare the languages accepted by the two automata.
5. If both automata accept exactly the same strings, the expressions are equivalent.

**Example:**

\\[ R_1=(a+b)^\* \\]

\\[ R_2=a^\*(ba^\*)^\* \\]

Both represent all strings over \\(\\{a,b\\}\\).

Therefore:

\\[ R_1\equiv R_2 \\]

## **6. Conversion of FA to Regular Expression Using Arden's Theorem**

Arden's Theorem is used to find a regular expression equivalent to a Finite Automaton.

**Theorem:**

If

\\[ R=Q+RP \\]

Then the solution is:

\\[ R=QP^\* \\]

Similarly, if

\\[ R=Q+PR \\]

Then:

\\[ R=P^\*Q \\]

**Condition:** The solution is unique if ε is not present in P.

**Steps to convert FA to RE:**

1. Assign a variable to each state representing the language accepted from that state to the final state.
2. Write equations based on transitions between states.
3. Include ε for a final state when the path can terminate there.
4. Rearrange equations into Arden's theorem form.
5. Apply Arden's theorem to eliminate variables.
6. Substitute the obtained expressions into the remaining equations.
7. Continue until the initial state's expression is obtained.
8. The final expression is the required regular expression.

**Example:**

Consider the equation:

\\[ R_1=aR_1+b \\]

Using Arden's theorem:

\\[ R_1=b+aR_1 \\]

Therefore:

\\[ R_1=a^\*b \\]

**Important:** Always arrange the equation carefully before applying Arden's theorem.

## **7. Pumping Lemma for Regular Languages**

The Pumping Lemma is used to prove that a language is **not regular**.

If L is a regular language, there exists a positive integer p called the pumping length such that every string w in L, where \\(|w|\geq p\\), can be divided into three parts:

\\[ w=xyz \\]

Such that:

1. \\(|xy|\leq p\\)
2. \\(|y|\geq1\\)
3. \\(xy^iz\in L\\), for every \\(i\geq0\\).

**Meaning:**

- x is the initial part of the string.
- y is the portion that is repeated.
- z is the remaining part.
- y must contain at least one symbol.
- Repeating or removing y must keep the string in L.

**Steps to prove a language is not regular:**

1. Assume that the given language is regular.
2. Let p be its pumping length.
3. Choose a string \\(w\in L\\) such that \\(|w|\geq p\\).
4. Divide w into xyz according to the pumping conditions.
5. Consider all possible valid divisions.
6. Choose a pumping value, usually \\(i=0\\) or \\(i=2\\).
7. Show that the resulting string does not belong to L.
8. This gives a contradiction; therefore, L is not regular.

**Example:**

\\[ L=\\{a^nb^n\mid n\geq0\\} \\]

Choose:

\\[ w=a^pb^p \\]

Since \\(|xy|\leq p\\), both x and y contain only a's.

Taking \\(i=0\\) removes y, resulting in fewer a's than b's.

Therefore:

\\[ xy^0z\notin L \\]

Hence, L is not regular.

**Important:** Pumping Lemma can prove that a language is not regular, but it cannot prove that a language is regular.

## **8. Closure Properties of Regular Languages**

Closure properties describe whether applying an operation to regular languages always produces another regular language.

**Regular languages are closed under:**

| Operation            | Property                      |
| -------------------- | ----------------------------- |
| Union                | \\(L_1\cup L_2\\) is regular  |
| Intersection         | \\(L_1\cap L_2\\) is regular  |
| Complement           | \\(\overline{L}\\) is regular |
| Difference           | \\(L_1-L_2\\) is regular      |
| Concatenation        | \\(L_1L_2\\) is regular       |
| Kleene Star          | \\(L^\*\\) is regular         |
| Reversal             | \\(L^R\\) is regular          |
| Homomorphism         | Result is regular             |
| Inverse Homomorphism | Result is regular             |

**Explanation:**

- Union combines strings from either language.
- Intersection contains strings common to both languages.
- Complement contains strings not present in the original language, relative to the same alphabet.
- Concatenation joins strings from two languages.
- Kleene Star allows zero or more repetitions.
- Reversal reverses the order of symbols in every string.

**Important:** Regular languages remain regular after applying any of these operations.

## **9. Applications of Regular Expressions**

Regular Expressions are widely used in computer science for identifying and processing patterns in text.

- **Lexical Analysis:** Identifies tokens such as keywords, identifiers and operators in compilers.
- **Pattern Matching:** Searches for specific patterns in text.
- **Text Searching:** Finds words and character sequences in files.
- **Input Validation:** Validates email addresses, phone numbers and other input formats.
- **Data Extraction:** Extracts required information from large text files.
- **Find and Replace:** Replaces matching patterns in text editors.
- **Log Analysis:** Searches error messages and specific patterns in system logs.
- **Data Filtering:** Filters records based on specified patterns.
