# **Unit I – Finite Automata**

## **1. Basic Concepts**

### **A. Symbols**

- A symbol is a single basic character used to form strings.
- It is the smallest building block of a language.
- Symbols are usually represented using lowercase letters.

**Example:**

\\[ \Sigma=\\{a,b,0,1\\} \\]

Here, a, b, 0 and 1 are symbols.

### **B. Strings**

- A string is a finite sequence of symbols taken from an alphabet.
- A string can contain one or more symbols or may be empty.
- The empty string is represented by \\(\epsilon\\).
- The length of a string is the total number of symbols in it.

**Example:**

If \\(\Sigma=\\{a,b\\}\\), possible strings are:

\\[ a,\ b,\ ab,\ ba,\ aab,\ bba \\]

\\[ |\epsilon|=0,\quad |abba|=4 \\]

### **C. Languages**

- A language is a collection or set of strings formed using an alphabet.
- A language may contain a finite or infinite number of strings.
- A language is represented by L.

**Example:**

\\[ L=\\{a,ab,abb,abbb\\} \\]

### **D. Formal Languages**

- A formal language is a set of strings formed using a specific alphabet and defined rules.
- It follows mathematical and logical structures.
- It is used in automata theory, compiler design and programming languages.
- Formal languages are classified into regular, context-free, context-sensitive and recursively enumerable languages.

**Important terms:**

| Term                          | Meaning                                  |
| ----------------------------- | ---------------------------------------- |
| Alphabet (\\(\Sigma\\))       | Finite set of symbols                    |
| String                        | Sequence of symbols                      |
| Empty String (\\(\epsilon\\)) | String of length zero                    |
| Language (L)                  | Set of strings                           |
| \\(\Sigma^\*\\)               | Set of all possible strings, including ε |
| \\(\Sigma^+\\)                | Set of all non-empty strings             |

## **2. Construction of DFA**

A **Deterministic Finite Automaton (DFA)** is a finite-state machine in which exactly one transition exists for every state and input symbol.

- It consists of a finite number of states.
- It reads the input string one symbol at a time.
- For every state and input symbol, there is exactly one next state.
- It does not allow ε-transitions.
- It accepts a string if the machine reaches a final state after reading the entire input.

**Formal representation:**

\\[ M=(Q,\Sigma,\delta,q_0,F) \\]

Where:

- Q – Finite set of states.
- Σ – Input alphabet.
- δ – Transition function.
- \\(q_0\\) – Initial state.
- F – Set of final states.

**Transition function:**

\\[ \delta:Q\times\Sigma\rightarrow Q \\]

**Steps to construct a DFA:**

1. Understand the language or condition to be accepted.
2. Identify the required states.
3. Mark the initial state.
4. Define transitions for every input symbol from every state.
5. Identify the final states.
6. Ensure every state has exactly one transition for each input symbol.
7. Draw the state transition diagram or prepare the transition table.
8. Test the DFA using accepted and rejected strings.

**Example:** DFA accepting strings ending with `ab`.

## **3. Construction of NFA**

A **Non-Deterministic Finite Automaton (NFA)** is a finite-state machine in which a state and input symbol may have zero, one or multiple possible next states.

- It consists of a finite number of states.
- Multiple transitions may exist for the same input symbol.
- A transition may also be absent.
- It does not necessarily require an ε-transition.
- A string is accepted if at least one possible path reaches a final state after consuming the entire input.

**Formal representation:**

\\[ M=(Q,\Sigma,\delta,q_0,F) \\]

**Transition function:**

\\[ \delta:Q\times\Sigma\rightarrow 2^Q \\]

Here, \\(2^Q\\) represents the power set of Q.

**Steps to construct an NFA:**

1. Understand the language to be accepted.
2. Identify the required states.
3. Mark the initial state.
4. Define possible transitions for each input symbol.
5. Allow multiple transitions from a state for the same input symbol, if required.
6. Identify the final states.
7. Draw the transition diagram or table.
8. Test the automaton with sample strings.

**Example:** NFA accepting strings containing `ab`.

## **4. Conversion of NFA to DFA**

An NFA can be converted into an equivalent DFA using the **Subset Construction Method**.

- Each DFA state represents a set of NFA states.
- The initial DFA state is the set containing the NFA initial state.
- Transitions are calculated by combining the possible NFA transitions.
- A DFA state is final if its set contains at least one NFA final state.

**Steps:**

1. Write the initial NFA state as the initial DFA state.
2. Calculate transitions for every input symbol.
3. Combine all possible destination states into a set.
4. Treat each new set as one DFA state.
5. Repeat until no new state sets are generated.
6. Mark any set containing an NFA final state as a final DFA state.
7. Prepare the final transition table.
8. Draw the equivalent DFA.

**Example:**

Suppose the NFA has:

\\[ \delta(q_0,a)=\\{q_0,q_1\\} \\]

Then the corresponding DFA transition is:

\\[ \delta_D(\\{q_0\\},a)=\\{q_0,q_1\\} \\]

The set \\(\\{q_0,q_1\\}\\) becomes a single DFA state.

**Important:** Every NFA has an equivalent DFA, and both accept the same language.

## **5. Conversion of ε-NFA to DFA**

An ε-NFA is an NFA that allows transitions without consuming any input symbol.

The conversion uses **ε-Closure and Subset Construction**.

**ε-Closure:**

The ε-closure of a state is the set of all states reachable from that state using zero or more ε-transitions, including the state itself.

**Steps:**

1. Find the ε-closure of the initial state.
2. Treat this closure as the initial DFA state.
3. For each input symbol, find all reachable states.
4. Calculate the ε-closure of the resulting states.
5. Combine these states to form a new DFA state.
6. Repeat for all newly generated states and input symbols.
7. Mark a DFA state as final if it contains at least one final state of the ε-NFA.
8. Continue until no new states are generated.

**Formula:**

\\[ \delta_D(S,a)=\epsilon\text{-closure}(\text{move}(S,a)) \\]

Where:

- S – Set of current states.
- a – Input symbol.
- move(S,a) – States reachable by consuming a.
- ε-closure – All states reachable through ε-transitions.

**Important difference:**

| NFA to DFA                           | ε-NFA to DFA                                         |
| ------------------------------------ | ---------------------------------------------------- |
| Uses subset construction.            | Uses ε-closure and subset construction.              |
| No ε-transitions.                    | Allows ε-transitions.                                |
| Initial state is a single NFA state. | Initial state is the ε-closure of the initial state. |
| Combines possible transitions.       | Combines transitions and ε-closures.                 |

## **6. Finite Automata as Language Acceptors**

A Finite Automaton is called a language acceptor because it determines whether a given string belongs to a particular language.

- It reads the input string from left to right.
- It starts from the initial state.
- It changes states according to the transition function.
- It processes one input symbol at a time.
- After reading the complete string, it checks the current state.
- If the current state is final, the string is accepted.
- Otherwise, the string is rejected.
- The set of all strings accepted by the automaton is called its language.

**Mathematical representation:**

\\[ L(M)=\\{w\in\Sigma^\*\mid\delta^\*(q_0,w)\in F\\} \\]

Where:

- \\(L(M)\\) – Language accepted by the automaton.
- w – Input string.
- \\(\delta^\*\\) – Extended transition function.
- \\(q_0\\) – Initial state.
- F – Set of final states.

**Example:**

A DFA designed to accept strings ending with `1` will accept:

\\[ 1,\ 01,\ 101,\ 111 \\]

It will reject:

\\[ 0,\ 10,\ 100 \\]

## **7. Moore Machine and Mealy Machine**

Both Moore and Mealy machines are finite-state machines that produce outputs based on input symbols and states.

### **A. Moore Machine**

A Moore Machine is a finite-state machine in which the output depends only on the current state.

- Each state has a fixed output.
- Output changes only when the machine changes state.
- Output is associated with states.
- It generally requires more states than an equivalent Mealy machine.

**Formal representation:**

\\[ M=(Q,\Sigma,\Delta,\delta,\lambda,q_0) \\]

Where:

- Q – Set of states.
- Σ – Input alphabet.
- Δ – Output alphabet.
- δ – Transition function.
- λ – Output function.
- \\(q_0\\) – Initial state.

**Output function:**

\\[ \lambda:Q\rightarrow\Delta \\]

### **B. Mealy Machine**

A Mealy Machine is a finite-state machine in which the output depends on the current state and current input symbol.

- Output is associated with transitions.
- Output may change when an input is received.
- It generally requires fewer states than an equivalent Moore machine.
- Output is written along with the transition label.

**Formal representation:**

\\[ M=(Q,\Sigma,\Delta,\delta,\lambda,q_0) \\]

**Output function:**

\\[ \lambda:Q\times\Sigma\rightarrow\Delta \\]

## **8. Conversion of Moore Machine to Mealy Machine and Vice Versa**

### **A. Moore to Mealy Conversion**

**Steps:**

1. Identify all states and their outputs in the Moore machine.
2. Examine each transition from a state.
3. Write the output of the destination state on the corresponding transition.
4. Keep the same states and input transitions.
5. Remove the outputs associated with individual states.
6. The resulting machine is a Mealy machine.

**Key rule:**

For a transition from state p to state q on input a:

\\[ p\xrightarrow{a}q \\]

The Mealy output is:

\\[ \lambda(q) \\]

That is, the output of the destination state.

### **B. Mealy to Moore Conversion**

**Steps:**

1. Examine the outputs on all transitions entering each state.
2. If a state has incoming transitions with different outputs, split that state.
3. Create separate copies of the state for different incoming outputs.
4. Assign the corresponding output to each new state.
5. Redirect transitions to the appropriate state copies.
6. Ensure every state has a fixed output.
7. The resulting machine is a Moore machine.

**Key rule:** Each Moore state must have only one fixed output.

**Difference in conversion:**

| Moore to Mealy                                | Mealy to Moore                                |
| --------------------------------------------- | --------------------------------------------- |
| Output is shifted from states to transitions. | Output is shifted from transitions to states. |
| Output is taken from destination state.       | States may need to be split.                  |
| Usually does not require extra states.        | May require additional states.                |

**Note:** Conversion may cause an initial-output difference because Moore machines produce an output for the initial state, whereas Mealy machines produce outputs on transitions.

## **9. Limitations of Finite Automata**

Finite Automata have limited memory because they contain only a finite number of states.

- They cannot store an unlimited amount of information.
- They cannot count an arbitrary number of symbols.
- They cannot recognize languages requiring matching or balancing of symbols.
- They cannot recognize languages such as \\(L=\\{a^nb^n\mid n\geq0\\}\\).
- They cannot recognize balanced parentheses of arbitrary depth.
- They cannot handle unlimited nested structures.
- They cannot recognize non-regular languages.
- They have less computational power than Pushdown Automata and Turing Machines.

**Example:**

\\[ L=\\{a^nb^n\mid n\geq0\\} \\]

This language requires the number of a's to be equal to the number of b's.

A finite automaton cannot remember an arbitrary number of a's to compare with the number of b's.

**Solution:** A Pushdown Automaton can recognize this language using its stack.
